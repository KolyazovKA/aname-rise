# Техническое задание: таймер в окне календаря

## 1. Итоговый интерфейс

- Круговой индикатор прогресса с временем внутри.
- Одна кнопка переключения запуска и паузы.
- Отдельная кнопка сброса.
- Календарь сохраняет текущий внешний вид и поведение.

## 2. Размер окна и компоновка

Файл: `src/popup.rs`.

Сейчас размер календарного окна — `308 × 316`.

Предлагаемый размер — примерно `520 × 316`. Это отправная точка, а не обязательное число: проверить фактические размеры календаря, внутренние отступы и минимальную ширину таймера.

Требования:

- Календарь не должен растягиваться на всю ширину окна.
- Таймер занимает отдельную область справа.
- Между календарём и таймером — небольшой визуальный разделитель или отступ.
- Сохранить существующую рамку и внутренние отступы popup.
- Не менять размеры и расположение остальных типов popup.

Если достаточно изменить ширину календарного popup и передать календарю фиксированную ширину, не вводить отдельную систему компоновки.

## 3. Логика таймера

Начальная длительность — 25 минут.

| Действие               | Результат                          |
| ---------------------- | ---------------------------------- |
| Нажатие Play           | Запуск отсчёта                     |
| Нажатие Pause          | Пауза с сохранением остатка        |
| Повторное нажатие Play | Продолжение отсчёта                |
| Нажатие Reset          | Возврат к 25:00, таймер остановлен |
| Достижение 00:00       | Остановка таймера                  |

Дополнительные правила:

- Таймер изначально остановлен.
- После достижения нуля кнопка запуска не должна запускать отрицательный или новый отсчёт. Для нового цикла нужен сброс.
- Закрытие календаря не останавливает таймер.
- Повторное открытие календаря показывает актуальное оставшееся время.
- Переключение месяца не влияет на таймер.

## 4. Реализация отсчёта

Не уменьшать счётчик на одну секунду при каждом тике. Такой подход постепенно накапливает погрешность.

Использовать `std::time::Instant`:

- При запуске сохранить момент окончания отсчёта.
- При паузе вычислить и сохранить оставшееся время.
- При продолжении установить новый момент окончания.
- При отображении вычислять остаток из текущего времени и дедлайна.
- Ограничить результат нулём.

Так таймер продолжит работать корректно, даже если интерфейс обновляется с задержками.

Не создавать отдельный поток или цикл обновления, пока не проверен существующий механизм обновления `Service` в проекте. Использовать уже имеющийся механизм, если он подходит.

## 5. Состояние

Перед реализацией проверить `src/state.rs` и существующие сервисы.

Минимально необходимое состояние:

- оставшееся время, когда таймер остановлен;
- момент окончания отсчёта, когда таймер запущен.

Не добавлять:

- историю сессий;
- пользовательские интервалы;
- настройки длительности;
- статистику;
- уведомления;
- сохранение состояния после перезапуска приложения.

Для этой версии достаточно состояния в памяти процесса.

Если существующий `Ui` — подходящее место для состояния таймера, использовать его. Отдельный `Service` вводить только в случае, если без него таймер не сможет обновляться при закрытом popup.

## 6. Круговой индикатор

Индикатор должен отражать оставшееся время:

- полный круг при `25:00`;
- постепенно уменьшающаяся дуга;
- пустой круг при `00:00`.

Цвета:

- фоновая окружность — существующий `theme.border`;
- активная дуга — `theme.accent`.

Проверить API `amane`: есть ли поддержка дуг, окружностей или SVG.

Использовать самый простой доступный способ отрисовки. Не добавлять библиотеку ради одной окружности. Если SDK не поддерживает нужную геометрию, выбрать минимальное решение на уже доступных средствах проекта.

## 7. Кнопки

Использовать существующие компоненты и обработчики из `src/ui.rs`.

Кнопка запуска/паузы:

- `play`, когда таймер остановлен;
- `pause`, когда таймер работает;
- одна и та же кнопка переключает состояние.

Кнопка сброса:

- иконка `rotate-ccw`;
- всегда доступна;
- сбрасывает таймер на 25 минут и останавливает его.

Не добавлять подписи, дополнительные кнопки и отдельные режимы.

## 8. Файлы, которые можно затронуть

| Файл              | Изменение                                                                             |
| ----------------- | ------------------------------------------------------------------------------------- |
| `src/popup.rs`    | Расширение окна календаря и компоновка                                                |
| `src/calendar.rs` | Передача календарю ограниченной ширины                                                |

Не создавать новые файлы без необходимости.

## 9. Проверка

После реализации проверить:

1. Таймер отображает `25:00` при открытии.
2. Play запускает отсчёт.
3. Pause останавливает его без потери остатка.
4. Повторный Play продолжает отсчёт.
5. Reset возвращает `25:00`.
6. При достижении нуля таймер останавливается.
7. Закрытие и повторное открытие календаря не сбрасывает отсчёт.
8. Переключение месяца не сбрасывает отсчёт.
9. Круговой индикатор соответствует оставшемуся времени.
10. Остальные popup не изменились.

Запустить существующие проверки проекта: форматирование, сборку и тесты, если они предусмотрены.
